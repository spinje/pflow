## What "live recording" means

Each case runs `pflow run` against a real provider once, captures the
produced trace JSON to `_shared/fixtures/`, then commits the trace.
Subsequent `verify.sh` runs use the committed fixture — they DO NOT call the
provider again. Re-recording is a one-time operation per change to provider
behavior or trace format.

## Required env

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export GEMINI_API_KEY=AI...
```

Agents without API keys cannot record these cases. They CAN still execute
the rest of `verify.sh` once the trace fixtures are committed.

## Recording flow per case

1. Create the case folder + workflow.pflow.md.
2. Run pflow once with API keys set:

   ```bash
   export BASELINE_DIR=/abs/path/to/baseline
   export BASELINE_CASE_DIR=$BASELINE_DIR/10-live-recordings/01-anthropic-basic
   export BASELINE_HOME=$BASELINE_CASE_DIR/.run-home
   rm -rf "$BASELINE_HOME"
   mkdir -p "$BASELINE_HOME/.pflow/debug"

   HOME="$BASELINE_HOME" uv run pflow run \
     "$BASELINE_CASE_DIR/workflow.pflow.md" \
     article="$(cat $BASELINE_DIR/_shared/long-stable-text.txt)"
   ```

3. Locate the produced trace, copy to `_shared/fixtures/`:

   ```bash
   trace=$(ls -1t $BASELINE_HOME/.pflow/debug/*.json | head -1)
   cp "$trace" "$BASELINE_DIR/_shared/fixtures/live-anthropic-basic.trace.json"
   ```

4. Commit the trace fixture.

5. Write the case's `command.sh` to use `--from-trace` against the committed
   fixture:

   ```bash
   #!/usr/bin/env bash
   set -uo pipefail
   cd "$BASELINE_REPO_ROOT"
   uv run pflow analyze-cache \
     "$BASELINE_DIR/_shared/workflows/smoke-with-cache.pflow.md" \
     --from-trace "$BASELINE_DIR/_shared/fixtures/live-anthropic-basic.trace.json" \
     context="ignored-by-trace-mode"
   ```

6. Run `run-case.sh <case-dir> --write` to capture the analyze-cache output.

7. Inspect the captured output personally — verify cache_creation /
   cache_read tokens look right, confidence label is `high_from_trace`,
   per-call data_source is `trace`.

## Trace-as-fixture contract

Once committed:
- Trace JSON files in `_shared/fixtures/` MUST NOT be regenerated unless
  trace format changes (e.g., bumping past 2.1.0).
- The trace's `workflow_path` field encodes the absolute path the producer
  saw. For auto-load tests, command.sh must patch the field at runtime to
  match the case's local workflow path. For `--from-trace` tests this is
  irrelevant — the explicit flag bypasses the path matcher.

## Trace 2.0.0 backcompat fixture

`_shared/fixtures/sample-2.0.0-trace.json` is generated by stripping `format_version`,
`workflow_path`, and per-event cache fields from the 2.1.0 sample. It exists for
the (currently-untested) "auto-load skips 2.0.0" case in surface 03 (deferred
during compression).

## Why we don't record on every CI run

LLM responses jitter at the token level. Cache-creation/cache-read counts
are stable for fixed input bytes (provider deterministic on this) but
runtime metadata (durations, end_time) varies. The trace fixture is
committed so verify-mode re-uses it deterministically. Re-recording when
the fixture goes stale is the rare-but-deliberate operation.
