# Song Creator

Takes a single core concept and a per-concept material palette, then produces a finished song through a multi-stage creative pipeline. Each stage builds on the previous: creative direction → song architecture → easter eggs → chorus-first writing → two-phase review/rewrite (emotional architecture, then craft polish) → final version.

Used as a **sub-workflow** by `lyrics-generator.pflow.md`, batched across multiple concepts in parallel to explore different creative paths simultaneously.

## Inputs

### concept

The core concept for this song — the ONE thing it's about. Generated by the parent workflow's concept exploration step. Enriched with diversity assignments (genre family, narrator hint, narrator type) by the enforce-diversity step.

* `title` — working title for this creative direction
* `core_idea` — one sentence describing the singular focus
* `angle` — how this concept approaches the source material differently from others
* `genre_family` — assigned genre family for diversity (e.g., Folk/Americana, Electronic/Synth)
* `narrator_hint` — assigned narrator perspective
* `narrator_type` — "natural" (obvious choice) or "wild_card" (intentionally non-obvious)
* `reasoning` — why this narrator and genre combination serves this concept

- type: object
- required: true

### concept_brief

Per-concept material palette curated from source analyses. Tailored to this concept's emotional core, genre, and narrator — includes metaphor mappings, kill moments, contradictions, recognition moments, narrator's blind spot, vocabulary, and scenes. This replaces the old shared creative brief.

- type: string
- required: true

## Steps

### creative-direction

Make the five foundational creative decisions that shape everything about this song: genre (within the assigned family), voice (developing the assigned narrator into a full character), contrast strategy, audience context, and tonal register. Each decision cascades through the entire pipeline — genre affects structure, voice affects word choice, contrast affects emotional impact.

Forces exploration before commitment: considers multiple sub-genres within the assigned family, develops the narrator into a complete persona with vocabulary and emotional arc.

- type: llm
- temperature: 0.9
- reasoning_effort: none
- timeout: 300
- prompt_cache: [concept, concept_brief]
- prompt: ./creative-direction.prompt.md

### song-architecture

Create the structural blueprint — the skeleton that the writer will flesh out. Defines section layout, per-section narrative arc (what the listener learns/feels at each point), emotional trajectory, image system, hook meaning-shift, opening line strategy, and genre-informed musical structure (line count, syllable range, rhyme scheme per section).

Includes the Swap Test (can sections be reordered?), Chorus Shift Test (does meaning change each time?), and Bridge Test (is the bridge a concrete scene with pre-assigned source material, not an abstract function?).

- type: llm
- temperature: 0.5
- timeout: 300
- prompt_cache: [concept, concept_brief, creative-direction.response]
- prompt: ./song-architecture.prompt.md

### easter-eggs

Identify 3-5 opportunities for hidden depth that reward attentive listeners without being necessary for the song to work. Prioritizes meaning-driven depth (double meanings, motif evolution, source callbacks) over structural tricks. Structural proposals must pass a singability test — rigid constraints that could force awkward phrasing are rejected.

Each opportunity specifies where it goes, how the surface reading works independently, what the hidden reading reveals, and whether a casual listener would notice.

- type: llm
- temperature: 0.9
- reasoning_effort: none
- timeout: 300
- prompt_cache: [concept, concept_brief, creative-direction.response, song-architecture.response]
- prompt: ./easter-eggs.prompt.md

### choose-chorus

Generate ~34 chorus options through 13 creative lenses × 2 models, score them individually against a rubric, and select the top 3. The winning chorus becomes a fixed constraint for the songwriter — the hook phrase is set, the core imagery is set. Runners-up are provided as reference material.

This is the "chorus-first" approach: explore the creative space for the most important part of the song BEFORE writing the full song. The songwriter then builds verses, bridge, and structure around the best chorus rather than writing everything in one pass and hoping the chorus lands.

- type: workflow
- workflow: ./chorus-chooser/chorus-chooser.pflow.md
- inputs:
    concept: ${concept}
    creative_direction: ${creative-direction.response}
    architecture: ${song-architecture.response}
    creative_brief: ${concept_brief}

### write-lyrics

The main creative step — turn architecture into art. Receives the complete blueprint (concept, creative direction, song architecture, easter eggs, material palette) PLUS the pre-selected chorus from the chorus-chooser. The writer builds the song around the winning chorus rather than writing everything from scratch.

Balances two sets of constraints: content quality rules (no clichés, no AI tells, concrete imagery, earned emotion, negative space) and song craft rules (follow syllable range, follow rhyme scheme, singability, breathing room). Both are essential — content rules without song craft produces prose; song craft without content rules produces generic lyrics.

- type: llm
- temperature: 0.9
- reasoning_effort: none
- timeout: 300
- prompt_cache: [concept, concept_brief, creative-direction.response, song-architecture.response, easter-eggs.response]
- prompt: ./write-lyrics.prompt.md

### emotional-reviews

Four specialist critics review the draft lyrics for emotional architecture and legibility — whether the song's Kill Moments land, The Unsaid is felt, the Narrator's Blind Spot creates dramatic irony, the narrative arc holds, the imagery forms a coherent world, and whether a listener with zero context can actually follow what the song is about. These are the "does the song WORK?" reviews.

Three are context-aware (fidelity) reviewers that receive the brief and architecture and check execution against intent. The fourth is context-free: `review-stranger-summary` receives ONLY the lyrics and judges legibility the way a first-time listener would — whether the song is CLEAR, PARTIAL, or OPAQUE to someone without the blueprint. Keeping this reviewer input-isolated is deliberate: it catches comprehension failures the fidelity reviewers structurally cannot, because they unconsciously fill gaps from the inputs they were given.

Each review is a sub-workflow callable both from this pipeline and standalone by agents.

- type: workflow
- workflow: ${item.workflow}
- inputs: ${item.inputs}

```yaml batch
items:
  - focus: emotional-architecture
    workflow: ./reviews/review-emotional-architecture.pflow.md
```

### format-emotional-reviews

Format the emotional architecture reviews into readable markdown.

- type: code
- inputs:
    reviews: ${emotional-reviews.results}

```python code
reviews: list

review_labels = {
    "emotional-architecture": "Emotional Architecture",
    "narrative": "Narrative Arc",
    "imagery": "Imagery Quality",
    "stranger-summary": "Stranger Summary (Legibility)"
}

sections = []
for review in reviews:
    if isinstance(review, dict):
        focus = "unknown"
        item = review.get("item", {})
        if isinstance(item, dict):
            focus = item.get("focus", "unknown")
        label = review_labels.get(focus, focus)
        response = review.get("review_text", review.get("response", str(review)))
        sections.append(f"## {label}\n\n{response}")
    else:
        sections.append(str(review))

result: str = "\n\n---\n\n".join(sections)
```

### rewrite-emotional

Structural revision focused on emotional architecture. The rewriter can move whole sections, rewrite verses to build toward Kill Moments, fix Blind Spot confessions, and create breathing room. Does NOT worry about clichés, AI vocabulary, or syllable counts — those are handled by the craft rewriter next.

- type: llm
- temperature: 1
- reasoning_effort: none
- timeout: 300
- prompt_cache: [concept, concept_brief, creative-direction.response, song-architecture.response, easter-eggs.response]
- prompt: ./rewrite-emotional.prompt.md

### extract-emotional-lyrics

Split the emotional rewrite output into deliberation and lyrics for the craft review phase.

- type: code
- inputs:
    rewrite_output: ${rewrite-emotional.response}

```python code
rewrite_output: str

import re

lines = rewrite_output.split('\n')
lyrics_start = 0

for i, line in enumerate(lines):
    if re.match(r'^\[', line.strip()):
        lyrics_start = i
        for j in range(i - 1, -1, -1):
            if lines[j].strip():
                lyrics_start = j
                break
        break
    if line.startswith('# ') and not line.startswith('## '):
        lyrics_start = i
        break

deliberation = '\n'.join(lines[:lyrics_start]).strip()
lyrics = '\n'.join(lines[lyrics_start:]).strip()
result: dict = {"deliberation": deliberation, "lyrics": lyrics}
```

Each review is a sub-workflow callable both from this pipeline and standalone by agents.

- type: workflow

### rewrite-craft

Final craft polish — fixes AI tells, replaces clichés, improves singability, tightens syllable counts, fixes rhyme issues. Does NOT touch the emotional architecture established by the previous rewriter.

### generate-suno-prompt

Generate a Suno / music-gen style prompt for this song. Takes the creative direction (genre, voice, mood, instrumentation, arrangement arc) and the finished lyrics, and produces a three-layer prompt (descriptive paragraph + `Keywords:` line + optional `Exclude styles:` line) that works across both prose-interpreting and keyword-interpreting music generation models.

- type: llm
- temperature: 0.3
- reasoning_effort: none
- timeout: 240
- prompt_cache: [creative-direction.response]
- prompt: ./generate-suno-prompt.prompt.md
