## Read First — the load-bearing block
- **What exists now:** one module, `src/pflow/core/templates.py`, owns the `${…}` language: a regex-tokenized, total, immutable parse (`parse` → `Template` of `Text | Expression | Issue`; `Reference` paths of `Field | Index | DynamicIndex`), one value walk (`lookup`/`_walk`), `resolve()` returning a `Resolution(value, unresolved, issues)`, the shared type rules, and the permanent string-helper facade `TemplateResolver`. The validator keeps its own structure walk over the same parse (ADR-0006).
- **Read these first:** `core/templates.py` (`_SCAN`, `_tokenize`, `parse`, `parse_path`, `Resolution`, `resolve`, `_resolve_string`, `TemplateResolver`); `core/CLAUDE.md` → "Template language" (the rules' one home); `core/workflow/template_surfaces.py` (`iter_template_surfaces`); `runtime/template_validation/validator.py::_validate_malformed_templates` + `operands.py` (`OperandPolicy`, `iter_template_operands`); `runtime/engine/template_resolution.py::resolve_templates`.
- **Invariants that must NOT break:**
  1. **Every unescaped `${` is an `Expression` or an `Issue`, never `Text`.** Break it and malformed templates route as static params and reach nodes as literal text with exit 0 (the converse-silent class this task ended).
  2. **"Unresolved" is judged only from `Resolution.unresolved`/`.issues` of the AUTHOR template — never by scanning resolved text.** Scanning resolved output false-errors on upstream values containing `${…}` and on `$${x}` escapes, and misses rewritten-index misses (#630 class).
  3. **`parse()` runs on author text only** (bounded `lru_cache` keyed on text). `has_templates`/`has_references` are the uncached scans that may see resolved values. Routing runtime values through `parse` pollutes the cache and double-unescapes.
  4. **The AST is frozen and tuple-only; `Literal.value` is computed fresh per access.** A mutable cached node would leak across batch threads and the long-lived MCP server.
  5. **`extract_variables` / `Expression.operands` = VALUE view (outer references); `Expression.references` / `Template.references` = DEPENDENCY view (DynamicIndex inner refs included).** Using the value view where dependencies are meant silently drops inner refs (it happened twice — see Gotchas).
  6. **Every template-bearing surface is listed once, in `template_surfaces.py`.** The one Issue→ERROR pass and the reference passes enumerate it; a surface missing there is a surface where malformed templates go silent.
  7. **Cache hash and prepare render through ONE helper, `prompt_cache.render_cache_chunks`**; `CacheChunkIR.prose_before` stays escaped (graph build re-emits it as template text). Two render paths = cache-key/bytes divergence.
  8. **No trace field was added.** `__template_errors__` (which now carries `unresolved_expressions`/`issues`) never reaches the trace; the channels never ride `last_resolutions`.

## Patterns & Anti-Patterns
- **Phase-gated row corpus.** `tests/test_integration/test_template_parity.py`: one `Row` per (surface, template) with a validator outcome and a runtime outcome, each side driven through the REAL entry (`WorkflowRunner().validate` / per-surface direct drivers + an end-to-end run for validator-clean rows). During migration, future values sat as `xfail(strict=True, raises=AssertionError)` items naming the flipping phase, with harness preconditions raising `HarnessError` so a harness bug could never masquerade as an expected failure; every XPASS had to be explained by the phase's diff or the phase stopped. The scaffolding is gone now; the doctrine stays: **fix the divergence, never the row.** Reuse this shape for any cross-layer migration.
- **Mutation ledger per phase** (apply a named mutation to `src/`, run the targeted tests, restore from a byte copy, record what went red). It found missing rows in phases 1, 4a, 4b and 4c that green suites did not.
- **Vendored-legacy differential** for a refactor gate (phase 2 vendored the old walk from git into a throwaway test; 1177 path×context combos) — then delete it.
- **Two channels, not one:** `unresolved` (misses) and `issues` (malformed) stay distinct so the deferred #621 tolerance can relax Issues per surface without hiding misses.
- **Anti-patterns (each tried or proposed, each broke something):** `has_templates == bool(parse().expressions)` (re-breaks escape-only routing, #620); resolve-then-`TEMPLATE_PATTERN.search` the output; deriving "found" from `value is not None` (breaks found-`None` coalesce); unescaping `prose + value` together in cache rendering; classifying a normalizer input by "contains `${`" (the bare dynamic-index regression); lexical `split(".")` on template paths; a dict-wide unresolved set for optional-input injection (hides a required sibling sharing the text — inputs resolve per key).

## Gotchas & Non-Obvious Coupling
- **A facade helper's meaning change reaches every caller at once.** When `extract_variables` became the value view (4a), Pass 8 silently stopped flagging `${item.nope}` inside `${p.out_arr[${item.nope}]}` and upstream-stderr collection dropped the inner node — neither was in the 4a file list and no corpus row caught the first. Grep every caller of a facade helper whose semantics you change and ask "value or dependency view?".
- **The Issue span runs to the first `}`.** `${a[${i ?? 0}]}` is one Issue (correct); the same rule makes any *manufactured* `${prefix ${x}}` an Issue that swallows the inner reference — never wrap text that already contains `${` (why `_normalize_source` checks `is_simple` on the wrapped form).
- **Escape grammar:** `$${…}` consumes a brace-balanced body (one nesting level) through its closing `}`; an unclosed `$${` consumes only `$${`. The `(?<!\$)` lookbehind in `_SCAN` is an equivalent mutant (the escape alternative always wins first) — documented, not load-bearing.
- **`${x}\n` (one trailing newline, YAML `v: |`) must stay a simple, type-preserving template** — frozen behavior nothing pinned until the 4a review.
- **Grammar digits are ASCII `[0-9]`**, and a literal is admitted only if `try_parse_json` decodes it — `\d` admitted Unicode digits that crashed `resolve` and never matched the TS mirror.
- **`web/src/graph/scan.ts` mirrors `graph/scope.py` and must change in the same step**; a Python-vs-TS differential over 288 corpus templates found 0 diffs at close. The other TS grammar copies (`batchItems.ts`, `format.ts`, `sourceDecorate.ts`) are still unmigrated and lack the `$$` lookbehind.
- **Raw-path mode is a different reader on purpose:** `-o result.@type`, `read-fields result.dc:title`, MCP `read_fields result.my key` go through `_split_raw_path`, not the grammar. One shared walk means raw `x[0][1]` over a JSON-array-string element now resolves (pinned).
- **Cost-analysis tests monkeypatch call paths**: `test_cache_analysis_token_estimation.py` patches `token_estimation.resolve`; `test_cache_analysis_analyze.py` still patches `TemplateResolver.resolve_template`, which `sub_workflow_walker.py` (batch items) still calls. Migrating that site makes the patch silently stop intercepting.
- **The R5 message lives in two places** (`markdown_parser._parse_cache_code_block`, `data_flow._cache_var_roots`) by choice — a shared constant would make `data_flow` import the markdown parser. Both are pinned.
- **`render_cache_chunks`' undeclared-chunk warning is unreachable for compiled workflows** (`compile_workflow` rejects undeclared names); kept for hand-built contexts.
- **Task-159 baseline (`.taskmaster/tasks/task_159/baseline/verify.sh`) shows 7 pre-existing drifts** from main (#628's required `source:`, guide wording) — identical with this task's source swapped out. Not this task's.
