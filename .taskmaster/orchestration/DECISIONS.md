# DECISIONS.md — settled programme & process decisions

Numbered ledger of decisions below the ADR bar (process, routing, authority — not product
architecture; that's `context/adr/`). **Rows are not re-litigated**: new information that
contradicts one is a user escalation, and when a decision changes the row is updated in the same
breath. ADR-bar decisions get an ADR AND a row pointing at it. Write side: the main orchestrator.

The main orchestrator shifts from brief-writer-for-user-guided-builds to dispatcher: it never writes/reads plans, never runs deep-review — agents own their quality. |

| 10 | 2026-07-11 | **Session-read rule**: a booting main orchestrator reads the latest session file; if it's thin (short check-in, aborted session), it reads one further back until it hits a substantive one. | 11 | 2026-07-12 | **Session close is a ritual, not a filing chore**: the main orchestrator ends every session via the `/close-orchestrator-session` skill (drain — nothing closes hot; retrospect; make state true; refresh the rolling `BRAINDUMP.md`; propose process edits; commit). | 12 | 2026-07-13 | **PR commit review marker**: the first commit on a PR branch uses a normal message; every subsequent commit on that branch must include the exact marker `[skip review]` in its commit message. | User ruling. | 13 | 2026-07-13 | **Use 15-minute waits as the default while child agents run.** Child completion and user messages still interrupt immediately. | User ruling after observing that every wait timeout reinvokes the main agent; reduces wasteful polling. |
| 14 | 2026-07-13 | **Auto-reviewer comments are a merge gate.** The implementing agent must read and act on the automatic PR review comments (`claude-review` / Codex) before a PR is merge-ready; the orchestrator verifies this at the merge seam.
