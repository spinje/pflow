# DECISIONS.md — settled programme & process decisions

Numbered ledger of decisions below the ADR bar (process, routing, authority — not product
architecture; that's `context/adr/`). **Rows are not re-litigated**: new information that
contradicts one is a user escalation, and when a decision changes the row is updated in the same
breath. ADR-bar decisions get an ADR AND a row pointing at it. Write side: the main orchestrator.

| # | Date | Decision | Rationale / notes |
|---|------|----------|-------------------|
| 1 | 2026-07-11 | **Adopt the agent-hierarchy orchestration system** (ported from the loudkult/Nora systems, adapted to pflow). `ORCHESTRATION.md` is the canonical process contract; roles = main orchestrator / task-planner / task-orchestrator / phase-implementer; hierarchy exactly two levels. | User ruling after reviewing both source systems. The main orchestrator shifts from brief-writer-for-user-guided-builds to dispatcher: it never writes/reads plans, never runs deep-review — agents own their quality. |
| 2 | 2026-07-11 | **Three lanes**: A full task procedure · B GH-issue lane · C manual lane (the pre-restructure user-guided worktree flow, kept for open-ended or taste-verified work). Rubric in `ORCHESTRATION.md` "Lanes". | User: manual lane stays for tasks needing live guidance to the goal, "but these tasks will be less and less common". |
| 3 | 2026-07-11 | **Model routing** per `ORCHESTRATION.md` table: Fable = task planners always + opt-in with one-line justification; Opus = default for judgment; Sonnet = zero-ambiguity mechanical. Explicit `model` param on every launch. **Supersedes both 2026-07-03 rulings** ("never fable for research subagents" — folded into the table's Sonnet/Opus rows; "fable for the worktree builder" — now scoped to planners + lane C + justified opt-ins). User may override any routing per launch. | The monolithic "worktree builder" role the old rulings governed no longer exists in lanes A/B — it split into planner/orchestrator/implementers. |
| 4 | 2026-07-11 | **Merge authority is the main orchestrator's**: squash-merge after CI green on the merged result, then teardown (squash-safe prune check) + reconcile. Previously merges were user-only. | User ruling ("yes we adopt it"). Lane B agents merge their own PR after CI green. |
| 5 | 2026-07-11 | **Process-authorized commits** — narrow override of CLAUDE.md's never-commit-unless-instructed rule, scoped to the orchestration process: task agents commit on their feature branch; `/create-pr` pushes the feature branch; the main orchestrator commits spec-freshness/orchestration docs to `main` before provisioning (docs-commit-first). Pushes of `main` remain user-gated. | Worktrees are checkouts of `main`; uncommitted docs don't follow. Part of the adopted flow. |
| 6 | 2026-07-11 | **Orchestration state layout**: `orchestrator-progress-log.md` replaced by `CURRENT-STATE.md` (~80-line living header) + `sessions/session-NN.md` (append-only per session). Old log converted to `sessions/session-01.md`; full history also in git. | Consistency with the proven layout; the single-file log was growing unbounded. |
| 7 | 2026-07-11 | **Lane-B exclusions**: work touching `runtime/engine/`/`workflow_executor` or the trace format always takes the full task procedure, regardless of size. | These are pflow's highest-risk seams (the analog of loudkult's live-production migrations); they also carry the standing serialization rules. |
| 8 | 2026-07-11 | **ALL web-UI implementation phases route to Fable** (`web/` → `src/pflow/ui`) — never implemented inline by the task orchestrator, never a lower tier — with deliberate design/UX care: the plan states the phase's use case + look/feel intent, and visual quality/UX are acceptance criteria. **UI work ALWAYS invokes the `screenshot-pflow-web-ui` skill and verifies everything changed** — green component tests never close a UI phase. | User ruling (correcting the initial port, which had skipped loudkult's equivalent rule on the wrong premise that pflow's web UI is a mere dev tool). |
| 9 | 2026-07-11 | **Lane-B model policy**: the main orchestrator assesses the issue's complexity at pick time. **Opus is the floor — never lower** for the end-to-end agent. Genuinely complex issues (hard debugging, subtle root cause) warrant **Fable — but only with the user's per-launch approval**; never deploy Fable to lane B unasked. | User ruling. Scoped to lane B: lane A's Fable rules (#3 planners always, #8 UI phases always) are standing approvals and need no per-launch ask. |
| 10 | 2026-07-11 | **Session-read rule**: a booting main orchestrator reads the latest session file; if it's thin (short check-in, aborted session), it reads one further back until it hits a substantive one. Older files stay on-demand forensics. | User ruling (chose this over a fixed last-2 window). Preserves the forcing function — anything with forward value must reach CURRENT-STATE/a durable home before a session closes; session files are color, not state — while covering the thin-session case a fixed single read misses. |
| 11 | 2026-07-12 | **Session close is a ritual, not a filing chore**: the main orchestrator ends every session via the `/close-orchestrator-session` skill (drain — nothing closes hot; retrospect; make state true; refresh the rolling `braindump-main-orchestrator.md`; propose process edits; commit). The braindump joins the boot stack after the session file. | Ported from loudkult at the user's ask. pflow adaptations: lane-C terminal agents don't drain (they outlive the session — record their state in CURRENT-STATE); no prod-verify; pushing `main` stays user-gated (#5). |
