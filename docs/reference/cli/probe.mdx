## Usage

```bash
pflow probe <NODE> [PARAMS...]
pflow probe <NODE> [PARAMS...] --output-format json
```

`pflow probe` executes a single node for exploratory testing. By default it returns metadata and template paths rather than dumping raw output.

## Parameters

`name=value` arguments become the node's params; a value's type is inferred (`5` is a number, `true` a boolean, `{"a": 1}` an object). A `${VAR}` in a param is filled from the environment or from `pflow settings set-env` before the node runs — except inside a body (a shell command, a code block), whose `${…}` belongs to that language. A variable set in neither place refuses the probe with the commands that set it. The node runs the way a workflow step does: a file path in a param that takes content (`command`, `code`, `prompt`, `source`, `stdin`, `headers`, `output_schema`) — one starting with `./` or `../`, or one containing `/` and ending in `.md`, `.txt`, `.py`, `.sh`, `.yaml`, `.yml` or `.json` — is replaced by the file's content, and params are validated as `pflow run` validates a step: an unknown or malformed param is refused before the node runs.

## Failures and exit codes

| Code | Meaning | Output |
|------|---------|--------|
| `0` | The node succeeded | The output paths on stdout (or the JSON document) |
| `1` | The node ran and failed (a shell exit code, an HTTP error, a raised exception) | The error on stderr — the same diagnostic `pflow run` prints for that step |
| `2` | The probe was refused before the node ran: an unknown or ambiguous node, an invalid or unknown param, an unset `${VAR}` | The error on stderr |

With `--output-format json`, stdout always carries one document. A failure's document has `"success": false` and an `errors` list (plus `warnings`); a successful one has neither key.
