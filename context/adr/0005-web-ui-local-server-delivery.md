# The visualization UI is delivered as a local web server, not a static export or JSON dump

The React Flow workflow visualizer is served by a local ASGI server (Starlette) that exposes the GraphModel as JSON — and, later, runtime events as SSE — shipped behind an optional `pflow-cli[ui]` extra so the base CLI stays dependency-free. The first increment serves only the **static** structure (workflow catalog + per-workflow graph + click-to-read); the live multi-Run **observability** overlay is deliberately deferred — its event schema is pinned against this UI as a real consumer (Task 133, D1–D3) — but the wire contract already carries the structural `NodeId` (ADR-0003) so that overlay can later join runtime events losslessly.

Chosen over the two lower-effort options — a self-contained static HTML export, or emitting `asdict(GraphModel)` as JSON for a separate app — because the UI's real destination is live observability and a future hosted platform: a browser on a `file://` page cannot tail a growing Run log, so live streaming intrinsically needs a server, and an ASGI server is the same shape the cloud will run, written once instead of twice. The "keep the CLI lean" objection is answered by the `[ui]` extra (CLI/agent installs never receive the web stack), not by hand-rolling a stdlib server we'd discard once concurrent SSE and WebSocket (browser-side approval gates, Task 125) arrive.

Recorded so the server is not later "simplified" into a `--format json`/static-HTML emitter, which would re-break the live-overlay and cloud-reuse seams this shape exists to preserve. Deliberately **not** decided here (downstream implementation detail): the command surface, graph **layout** (client- vs server-side), the frontend's repo location, and the wire-contract shape (`render_react_flow` vs raw `asdict`).

## Considerations — the deferred wire-contract shape

Input for when the wire contract is decided (not decided here). `dataclasses.asdict(GraphModel)` is not React Flow's shape: `NodeId` serializes as a nested object (`{node_id, ancestor_path, port}`) where React Flow wants a single string `id`, and `Container` grouping must be mapped to `parentNode`. More consequentially, `asdict` **drops the derived views** — `is_terminal` / `is_decision` / `shadowed` are methods on `GraphModel`, not fields — so raw `asdict` forces the frontend to re-implement them, pushing model semantics into JS (the very thing this server shape exists to avoid). A `render_react_flow` translator keeps flat-id derivation and those predicates in Python (one source of truth); raw `asdict` is thinner in Python but moves that logic, and the risk of divergence, to the browser. Trap: the model's `shadowed()` is the general edge-suppression view, but the Mermaid renderer deliberately uses a *narrower* `_edge_shadowed_for_render` — a React Flow view must choose its own policy, not copy Mermaid's.
